### Вывод free до и после подключения swap
До создания файла подкачки у системы был раздел на 1.9Gi:
```
               total        used        free      shared  buff/cache   available
Mem:           3.8Gi       1.4Gi       2.1Gi       13Mi       531Mi       2.4Gi
Swap:          1.9Gi          0B       1.9Gi
```

После подключения файла swapfile на 512 МБ общий объем подкачки вырос до 2.4Gi:
```
               total        used        free      shared  buff/cache   available
Mem:           3.8Gi       2.5Gi       721Mi       31Mi       857Mi       1.3Gi
Swap:          2.4Gi          0B       2.4Gi
```
### Назначение команд
- fallocate: мгновенно выделяет место и создает пустой файл нужного размера на диске.   
- mkswap: наносит на файл специальную разметку, чтобы система распознала его как память подкачки.
- swapon: активирует этот файл, добавляя его емкость к общей виртуальной памяти.
### Параметр swappiness (10 против 60)
swappiness определяет, насколько охотно система переносит данные из оперативной памяти на диск.   
- Значение 60: стандартная настройка, ядро заранее и довольно часто сбрасывает неактивные страницы в swap.
- Значение 10: система будет максимально оттягивать этот момент и начнет использовать подкачку только при сильной нехватке оперативной памяти.
### Почему для баз данных swap рекомендуют отключать?
Жесткие диски работают в тысячи раз медленнее оперативной памяти. Если данные СУБД попадут в подкачку, база начнет критически тормозить, задерживая все зависимые процессы. Для баз данных безопаснее упасть с ошибкой нехватки памяти, чем зависнуть из-за медленного диска
